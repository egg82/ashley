# Method for 3D work

Most printable parts are not designed from nothing. Something close usually exists, and the job is to take what works
and change it until it fits the real object. Design from scratch only when nothing close exists or the part is simple
enough that writing it is faster than adapting it. Either way, every number the part depends on has to be real, and the
person has to be able to see which ones are not.

What goes wrong, again and again:

- A dimension was guessed that could have been looked up, measured or asked for.
- Space was gotten wrong: rotated parts, holes on the wrong face, a part that prints at a different angle from its
  picture.
- The tools said it worked on broken geometry. A union can silently drop a body, and the picture still looks fine.
- The part was checked at rest and not in use. A latch that clears a seated object can block it on the way in.
- A check passed because the number it compared was a guess, and the report said so only in small print.

## The pieces

A 3D job is two pieces and what they make.

- **A facts piece** (kind `facts`): every number the part depends on, each with where it came from. The
  body is JSON, `{"items": [{"name", "value", "unit", "source", "tolerance", "ref"}]}`. `name` is an
  identifier (`board_width`) used once. `unit` is `mm`, `deg`, `count`, `g`, `ml` or `min`, and lengths are always
  millimetres: convert what you are told. `source` is one of:
  - `measured`: the person measured it or told you it as a fact, or a file embodies it;
  - `datasheet`: published, with the address in `ref`;
  - `accepted`: you asked for it, and the person said to go with the value you had;
  - `bound`: something soft or varying (a strap that squashes, a cord that varies) whose true size is a range: `value`
    is the middle and `tolerance`, which must be above 0, is half the range;
  - `guessed`: anything else, including an estimate from a picture.
  `tolerance` is an optional plus-or-minus in the unit. `ref` is a short note: which edge, which tool, which page, which
  photo piece. Anything else is refused `bad_facts`.
  A **choice row** holds what kind of thing something is, in words: `{"kind": "choice", "name", "label", "value",
  "options", "source", "turn", "piece", "ref"}`. `label` names it for the person ("The lanyard"), `value` is plain words
  ("flat woven strap"), `options` the 2 to 6 values it could be. `source` is `stated` or `accepted` with `turn`, the
  person's message that says it; `seen` or `datasheet` with `piece`, the photo, file or page it comes from; or `guessed`.
- **A model piece** (kind `model`): build123d source, Python that builds the parts and ends by showing them. You run it
  with `bench_run`, language `build123d`. Keep one model piece per assembly; a second one only for a different object.
- **A file piece** (kind `file`) holding an existing design the person uploaded, as STL, 3MF or STEP. A model run is
  handed only the ones you name in `bench_run`'s `inputs` (`"inputs": [7]`), and the script gets each by the piece's id:
  `existing(7)`. Name every file the script calls `existing` on, and no others; together they may be about 0.75 MiB, and
  a named file that is not a model, does not fit or cannot be read refuses the run. The person can upload a smaller
  export.

## 1. Find what exists

Use look_up to find the best two or three existing designs for the job. Ask it to search Printables (its results carry
likes, downloads, makes and rating; a model's page has the author's description, print settings and file names), and
the web for what Printables lacks. For each one write what it gets right and what does not fit. Read how the good ones solve the hard part (retention for a mount, the load path for a hook); a mechanism
that recurs across well-reviewed designs is the one to keep, and a novel one is a guess. Comments from people who
printed it are facts: "perfect on a 42 mm bar" is worth keeping. Put the one or two best on the bench as site
pieces so the person can look. If one fits as it is, say so: the answer is "print that".

When a close design is on Printables, change it instead of redrawing it. printables_files lists a model's files by the
result number look_up gave it; bench_add_printables_file puts one on the bench as a file piece. Take the STEP when the
model has one (it keeps the real surfaces), else the 3MF, else the STL. When it comes back `needs_login` or `too_large`,
say so and ask the person to download the file from the model's page and upload it to the bench. For a design on any
other site you cannot download the file yourself: ask the person for the STL, 3MF or STEP, to upload it to the bench, and
say which page it is on. Once it is a file piece, the model script starts from it with `existing(piece_id)` (step 3).
Redraw from scratch only when nothing close exists or its files cannot be had.

## 2. Source every number

List each dimension the fit depends on and put it in the facts piece with its source.

- Look it up before guessing. A "typical layout" is a guess. Datasheets and maker drawings are `datasheet`; put the
  address in `ref`.
- A part the person says fits is measured. Its file is the source for every number it embodies (`source: measured`,
  `ref` naming the file piece). Measure from the file and do not ask for those numbers.
- Before asking how an existing part works, look at it (`bench_look`, or the file's geometry).
- **The form of what the part mates with is a fact with a source**, settled before you model: what kind of thing it is
  and its cross-section (a flat strap or a round cord, a tube or a bar). Take it from the person saying so or from
  looking at a photo piece with `bench_look`; a word the person used in passing, while answering something else, is not
  its form. Record it as a choice row with its options (`lanyard_form`: flat woven strap or round cord), `guessed` when
  neither settles it, and give each number only that form has `given` naming it (`strap_width` given `lanyard_form`).
  A photo settles the form (`seen`); a size you read off a photo stays `guessed` until the person gives or accepts it.
  The app shows each choice row to the person beside your reply, with its options to tap: never ask about one yourself.
- Ask the person for a measurement when it decides the fit and cannot be looked up or taken from a file. One question
  beats a reprint. Tell them how: which edge, with what tool, under what. The app shows the person each guessed number
  an unconfirmed check rests on, beside your reply, once. A row with `shown: true` in the open rows is already in front
  of them: do not ask again; it stays on the guess list you hand back and the work carries on over it.
- Every answer lands in its row at once, in the turn it arrives: a number they measured is `measured`; being told to go
  with your value is `accepted`; being told it varies or squashes is `bound`, from the smallest to the largest it can
  be. An answer that gives none of these still settles something: record what it settles and stop asking.
- A row whose source is not `guessed` keeps its number. Change it only when the person gives a new number or a new
  source exists (a new file, a datasheet), and change its `source` or `ref` to say which.
- Asked for options, build each as its own model run and show them, rather than describing them.
- Ask for the surroundings, not only the mating part: how much room is free, what sits beside it, which way it faces in
  use.
- A number you had to guess goes in as `guessed`, never as `measured`. Better to keep it off the part's critical path
  and ask.
- A correction from the person is a new value in the same row, not a second row. When the form turns out different,
  change its choice row and remove the numbers given the old one.

## 3. Model it

The model script reads the facts through a small helper that is already in the sandbox:

```
from build123d import *
from ashley_cad import check, measured, show

width = measured("board_width")
```

`measured(name)` returns the value in its unit (and fails, naming the rows, for an unknown name); `chosen(name)` returns
a choice row's value. Build every dimension that comes from the object out of `measured`, not out of a typed number, so
a changed measurement changes the part. `check` and `show` are below.

A `bound` row is a range, and the part must work at both ends of it. `measured(name)` gives the middle; the row's
`tolerance` is in `facts.json` beside the script (`{"items": [...]}`, each row as the piece holds it). Build the
fit so it holds the smallest and clears the largest, and write a `check` at each end.

- Model each printed piece in its print orientation, flat face on the bed, and give each a name and a role:
  `show(("sleeve", body, "enclosure"), ("gate", tongue, "flexure"), ("cord", rope, "reference", "cord_form"))`. The
  roles are `decorative`, `enclosure`, `structural`, `flexure` (bends in use), `moving`, `fit` (mates with something),
  `test` (a test print) and `reference` (a stand-in for a real object, never printed), which names the choice row of
  its form or the run fails; a fit against it rests on that row. Show an assembly with stand-ins for everything the
  part touches, with their real rounded edges wherever a lip or latch bears on them. A square stand-in hides a catch
  that pushes itself open on a rounded edge.
- Design for printing in layers: avoid overhangs steeper than about 45 degrees unless chamfered or an intended bridge,
  make horizontal holes teardrop-shaped, and give holes that turn horizontal on reorientation extra clearance. Print
  clearance is a named parameter at the top, not a number inside an expression.
- Pick the orientation from the load. Layers are weakest pulled apart, so the main load should not run across layer
  lines. If it does, reorient, add ribs or split the part.
- Give each feature one job. A part that flexes out of the way should not also carry the main load: stops carry load,
  a flexure only holds.
- Keep notes in a comment at the top of the model as you go: what each run found wrong and what you changed.

### Changing an existing model

```
from ashley_cad import check, cut_away, existing, joined, measured, show

holder = existing(7)                      # an STL is in millimetres unless you say existing(7, unit="in")
clip = ...                                # what you add, placed by the holder's own bounding box and faces
result = joined(holder, clip)             # fuses; cut_away(holder, tool) cuts
```

- Check the imported size against what you were told before building on it: put `existing(...)`'s bounding box in a
  `check` against a measurement of the real part.
- Place what you add from the imported shape's own geometry (`holder.bounding_box()`, a face's position), not from
  numbers typed from a picture of it.
- A boolean on a mesh can silently return only one of its inputs. `joined` and `cut_away` fail when the result lost or
  invented volume; use them, and still check `len(result.solids())` against what you expect.
- A mesh that does not close into a solid is refused with that reason. Ask the person for another export of the design,
  ideally STEP.
- Everything the original did stays as it was: the hole sizes and fits of the imported part are only as good as its
  file, so a fit on the original's surfaces rests on the person's measurement of the real object.

## 4. Check by numbers

A picture catches gross mistakes. Numbers catch what ruins a print. Write a `check` for every fit and every size the
part must hit:

```
check("board_gap", gap_measured_on_the_geometry, ">=", 0.3, tolerance=0.05, rests_on=["board_width"])
show(("case", case), ("lid", lid))
```

- `actual` is a number you measured on the geometry (a bounding box side, a hole diameter, the distance between two
  faces, a solid's volume), never a number you typed. `op` is `==`, `<=`, `>=`, `<` or `>`, against `target`, within
  `tolerance`. `rests_on` names the facts the check depends on; leave it out and it is every one read so far.
- The app, not you, gives each check `pass`, `fail` or `unconfirmed`, in the report `bench_run` returns.
- Check what a dropped body would show: the count of solids in each part (`len(part.solids())`) against what you
  expect, and the volume against a hand estimate.
- Check fits with arithmetic where the geometry cannot: bore against rod plus clearance, screw length against the
  stack. Check motion, not just the resting pose, for anything that moves or snaps: put the mating object at a few
  steps along its path and check the gap at each.
- When a run exits nonzero, read the error, fix the model, run again. Do not report a model that did not run.

## 5. Read the report, then look

Read what `bench_run` returned before you say anything about the result.

- **A `fail` is a finding, and so is a problem a slice or job reports.** Say which, what it got and what it needed,
  then fix the model and run again. Ask first only when the fix would change a row that is not `guessed`.
- **An `unconfirmed` check is not a pass.** It rests on a measurement that is `guessed` or missing, so the result is
  only as good as that guess. Say so in those words: name the check and the measurement. Ask the person to measure it
  only if its row is not `shown`; if it is, the question is already with them. Never call the part fitting while
  a check that decides the fit is unconfirmed.
- **An `overlaps` entry is a failure to fix before you say it is done.** It names two shown parts that occupy the same
  space, and each adds a failed `parts_apart` check. Separate parts shown together must not overlap: parts meant to touch
  are one part (`joined`), and a test print goes beside the model, offset in X, not on top of it.
- **A `print_gap` or `print_trapped_support` failure is a print that will fail.** Every run checks the printed parts
  flat on the bed: a gap under an overhang too small to print open, or too small to pull its support out of. Fix the
  model (open the gap, chamfer, reorient) before you call it done. The `print` section gives each part's support area
  and overhang islands; support is normal. When `print.skip_reason` is set, printing was not checked: say so.
- **A `pass` is a pass of the numbers you wrote.** A fit nobody wrote a check for is not checked.

Then look at it with `bench_look` on the model piece. You get four views (isometric, front, top, right) and the
person gets the same picture with your answer, so they can point at what looks wrong. The picture is for gross shape,
orientation and things you did not think to check; it never settles a fit. Look once, after the checks are in.

Whether the model fits the real object is your call, made from the report and the sources of the facts
together. There is no second opinion to hand it to. If you cannot make it honestly, because the numbers that decide it
are guesses, that is the answer you give.

## 6. Hand it back

- The model piece, with its STL and 3MF downloads, and which existing designs you built on.
- The checks: how many passed, which failed, which are unconfirmed and on what.
- The guess list, with what a wrong guess would break and how to measure it.
- A small test print first: a piece that tests only the critical fit (the clamp on the bar, a row of holes, the latch),
  with what to check on it.
- The print file for the orientation the person chose, at the front of the bench. When no run or job made that one,
  hand off its slice.
- The risks, ranked by what is most likely to fail on the first full print.

You are done when every check passes, none that decides the fit is unconfirmed, and the only risks left are ones a print
can answer. Those go in the test print plan. If the work stops with a guess still standing, say that it is standing.
