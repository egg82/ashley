Wrong implementations the blind Proton mailbox suite (app/tests/mail_proton_blind) must kill. Written from the design alone
(decisions.md, "Her mail is a port with two adapters, and Proton's runs as a leased Bridge", build parts 5 and 6), before the
implementation existed. Each line: id, where it would live (the adapter, `ashley.mail.imap`, unless said), the wrong behaviour,
and the test that should go red (abbreviated). The reconciler plants these in the real adapter; the ones marked [ref] were also
planted in a throwaway reference adapter and their verdicts are in mutant-run.txt beside this file.

Equivalent or untestable here (and why)
Q1   which IMAP commands are used for a label (COPY vs APPEND of the fetched message): the suite reads the end state in the fake Bridge, so both pass; a copy by APPEND would lose the shared read state in a real Bridge, which the fake models (flags are the message's), so a change of unread by a re-APPEND is caught by label: unread_*
Q2   a timeout on a server that never answers: the suite does not wait out `timeout_s` (20 s); a test would be slow. Left for the reconciler's own directed test with a small `timeout_s`
Q3   TLS: the fake serves plain, implicit TLS or STARTTLS (FakeBridge(tls=...), controls in test_mp_fake_bridge) but the contract tests run plain; pinning by fingerprint is part 4's record and the build's choice (assumption G3)
Q4   routing between Gmail's and Proton's adapters by connection kind: wire_adapter registers the Proton adapter alone; a router's own tests are the reconciler's
