Wrong implementations the blind changes suite (app/tests/mail_changes_blind) must kill. Written from the design alone
(decisions.md, "Her mail is a port with two adapters, and Proton's runs as a leased Bridge", build part 6), before the
implementation existed. Each line: id, where it would live, the wrong behaviour, and the test that should go red. Test
names are abbreviated to their distinctive words. The verdicts (killed, directed test added, equivalent) are filled in
after the planted-mutant run, below the list.

Verdicts (each mutant applied one at a time to the built code and run against this suite, the part's own tests
(test_mail_changes_gmail, test_mail_changes_tools, test_mail_change_limits) and tests/outside_ask, -x, per-run timeout
170 s; killed means the run went red). Variants carry a letter suffix (M7a-b, M13a-b, M16a-c, M23a-b, M26a-c, M27a-b,
M28a-b, M29-b, M32a-c, M33a-b, M43a-b, M44a-b, M45a, M47a-c, M52-b, M53a-c, M54a-b, M57a-b, M60a-b, M63a-b, M66a-b).
Killed: M1-M29 (every variant), M31, M33-M51, M53-M56, M57b, M58-M66, M68, M69, M32a, M32c.
Killed by a directed test added for it: M30 (a 5xx on a label change, whose answer is empty, reached the caller as
success: test_mail_changes_gmail: a_change_gmail_fails_with_an_empty_answer_is_unreachable); M52 (a label list given as one
string: test_mail_change_limits: labels_given_as_one_string_are_refused...); M57a (the body limit counted in bytes:
...a_body_is_counted_in_characters_not_bytes); M67 (a failure's log carrying what was sent or answered:
test_mail_changes_gmail: a_failed_send_logs_nothing_it_sent_or_was_answered).
Equivalent (no test can tell them apart, with the reason):
M32b  the chosen mailbox is looked up among the readable ones instead of the changeable ones: a speaker either is a
      member (every readable mailbox is changeable) or is not (none is, and the call answers not_connected before the
      lookup), so the two sets never differ where a lookup happens.
Not applied: M45b (no-op by construction, dropped). M61 has no code path to mutate: the body follows the headers because
`EmailMessage` serialises it so, and a body cannot be appended another way here.
